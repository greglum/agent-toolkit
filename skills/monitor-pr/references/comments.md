# Authorized PR replies

Confirm the target PR/thread and authority to post. Monitoring and review alone do not supply it.
Follow repository attribution rules. Do not guess model identities or impose an attribution
banner when no rule requests one. Preserve text the user explicitly asks to send verbatim.

Lead with the conclusion and cite current code, a check, or a reproduction. State uncertainty.
Check the full message, quotes and attachments for private information. Prepare literal text
in a body file or structured API field and preview Markdown before sending.

Verify the returned comment URL and read back the body. An uncertain create result requires
lookup before retrying. Resolve a thread only after the requested response is verified and
its finding is actually addressed or dismissed with evidence. If posting fails, leave resolution
pending. Do not turn a successful resolution into proof that code was fixed.
