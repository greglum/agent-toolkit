# 15. Footer Design

Observed: 2026-10-05. Depth: targeted web search, public homepage, Info, Browse taxonomy, and a Making Software detail page. Public material was readable without login. No original site's footer was interactively tested, and no contrast, keyboard, or performance measurements were made.

Research method: searched `site:footer.design footer gallery about terms`, opened the official site, and followed the primary pages listed below.

## Purpose and useful evidence

[Footer Design's Info page](https://www.footer.design/info) describes a spare-time curation project created to fill the need for footer-specific inspiration. It is aimed at designers choosing how a website ends, rather than a general component framework.

The [Browse page](https://www.footer.design/browse) separates site type from visual style. Types include SaaS, web apps, editorial, ecommerce, and portfolios; styles include minimal, grid, cards, typographic, calm, animated, and WebGL. This distinction is useful: a business category and an aesthetic treatment are different choices. They should not be collapsed into a single prompt such as “make it SaaS style.”

The sampled [Making Software entry](https://www.footer.design/sites/making-software) includes desktop and mobile image references, an original-site link, style tags, attribution, and an April 25, 2025 addition date. Its editorial note favors a small footer. That gives a counterexample to the assumption that polish requires an oversized closing section.

## Patterns and application fit

For a public app website, examine information grouping: product links, help, legal information, contact, and any final signup action. For a signed-in application, first establish whether a full-page footer belongs at all. A persistent app shell, bottom action bar, paginated table, or infinite list may make a marketing footer impractical. The gallery does not settle that product decision.

Useful reference notes should capture the footer's job, column hierarchy, relative type size, spacing between groups, and transition from the preceding content. A large brand wordmark can be appropriate on a portfolio and wasteful in a data-intensive tool. A quiet utility footer can be a complete design when users mainly need policies and support.

Use the desktop/mobile pair to ask which groups should stack, which headings remain visible, and whether the mobile order follows user priority. Do not infer responsive behavior from a single static image. Visit the original site if its behavior is relevant and public access is available.

## Reuse, access, and integration

The inspected pages provide inspiration, outbound links, images, and credits. No reusable component source, package dependency, or blanket asset license was verified. Public browsing was open in this sample; the “Start a project” link is a studio service, not evidence of a subscription requirement for the gallery. Rights to imagery, brand marks, fonts, and original code must be checked at their source before reuse. Our documentation should retain links and original observations rather than copied screenshot collections.

## Skill use and checks

Route here when footer content or the ending rhythm of a public page needs design work. Require a content inventory before choosing visual treatment. Compare one restrained and one expressive reference, then implement the smallest footer that makes required destinations easy to find.

Analytical checks: small legal text contrast, readable labels at zoom, keyboard order across columns, touch target spacing, link-purpose clarity, and form errors if a newsletter signup is included. Animation, audio, horizontal scrolling, and WebGL are optional gallery styles that may introduce cost without helping users finish a task. No listed entry was certified accessible or fast by this research.

Recheck selected references after redesigns, before asset reuse, or when adding legal/support destinations changes the information hierarchy.
