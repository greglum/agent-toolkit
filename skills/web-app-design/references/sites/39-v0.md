## Purpose and current capabilities

v0 is Vercel's browser-based generation and editing platform for web applications. It supports prompts, visual references, code editing, previews, and application integrations. Its screenshot documentation describes extracting layout, color, and component information from uploaded images. A future skill can use that as a way to explore a design direction with permitted reference material. The provider's claim of faithful recreation is not independent proof of rendering or rights to reproduce the reference. [Product](https://v0.app/), [screenshots and files](https://v0.app/docs/screenshots)

Design Mode allows selecting an element in a running preview, changing styles or giving an instruction, then applying the result to project source. This can make a targeted refinement more concrete than a vague request to make a page modern. It still needs a user-task brief and review of the final code. [Design Mode](https://v0.app/docs/design-mode)

## Design-system integration

The current Design Systems 2.0 workflow learns from actual component/token sources, consumer apps, documentation, and Figma references. It saves a focused skill and a starter application, asks for review before saving, and tracks updates. Its standard starter uses Next.js, shadcn/ui, and Tailwind, which may conflict with an existing app's own setup. Use an already approved system rather than creating a second one. [Current system documentation](https://v0.app/docs/design-systems-2)

The older `v0.dev/docs/design-systems` path redirected to a page explicitly labeled legacy. Its registry recipe is useful historical context, but should not be prescribed as the current universal integration. The new documentation says existing generated apps do not automatically change when the shared design-system skill changes. Version and source review therefore remain important. [Legacy reference](https://v0.app/docs/design-systems-legacy), [update behavior](https://v0.app/docs/design-systems-2)

## Fit, access, and rights

v0 can help produce and compare a bounded prototype or edit an authorized existing project. The FAQ documents imports from GitHub, Vercel projects, or ZIPs. For a working business app, import and integration can be more consequential than generating a standalone visual concept; provider access and source transfer require the identified scope to be authorized. Use the current harness when it can complete the task. [FAQ](https://v0.app/docs/faqs)

The FAQ says Vercel does not own generated code, but warns outputs can overlap third-party rights, be incomplete, or contain bugs. It also points to data preferences for content-training choices. Do not treat generation as an asset license or assume a private repository is safe to upload by default. Exact plan limits, credit charges, privacy settings, and commercial terms require use-time review. [Output rights and data preferences](https://v0.app/docs/faqs), [AI policy](https://v0.app/policy)

## Use in the design skill

Keep v0 optional. Supply only approved reference content, current components/tokens, key task states, and a bounded goal; inspect exported changes in the app's normal workflow. Do not infer publication authority from an available publish control.

**Analytical checks:** semantic controls, focus, forms, responsiveness, loading/error states, truthful data, dependencies, and bundle cost. Preview success is separate from local gates and deployed acceptance. Recheck current URLs, design-system version, import/privacy terms, plan limits, and target-browser behavior before use.
